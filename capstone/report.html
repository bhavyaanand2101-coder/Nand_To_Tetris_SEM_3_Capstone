1. Executive Summary & Objective

The objective of the Nand to Tetris Capstone Project is to demonstrate the complete, end-to-end integration of a functional general-purpose computer starting from fundamental logic chips to a running high-level graphical application. The project is structured across three core engineering phases:

  • Part A — Hardware Architecture (Hack Computer): Implement the complete hardware platform in HDL by constructing CPU.hdl, Memory.hdl, and Computer.hdl, verified via the official Nand to Tetris Hardware Simulator.
  • Part B — Software Toolchain (Python Assembler): Develop an independent two-pass assembler in Python (assembler.py) that translates symbolic Hack assembly into 16-bit binary machine code, incorporating line-number error reporting tailored to student parameter $K = 46$.
  • Part C — Machine Application (Box Program): Write and assemble Box.asm to dynamically poll the keyboard and render a black rectangular box ($48 \times 20$ pixels) at screen row 46 while any key is pressed, clearing it instantly upon release.

1. Computer Architecture & Chip Connections

The Hack Computer is a 16-bit Von Neumann architecture constructed from three interconnected chips:

  • CPU.hdl: Composed of an A-register, D-register, ALU, and Program Counter (PC). It decodes 16-bit instructions into control signals. For A-instructions (inst[15]=0), it loads the 15-bit constant into the A-register. For C-instructions (inst[15]=1), it selects ALU operands via Mux16(a=outA, b=inM, sel=inst[12]), executes the ALU operation, routes outputs to destination registers ($A, D, M$), and computes branch conditions (evaluating zr and ng against jump bits j1..j3) to update the PC.
  • Memory.hdl: Decodes address bits address[13..14]: 00/01 routes to RAM16K (addresses 0–16383); 10 routes to Screen (16384–24575); 11 routes to Keyboard (address 24576). A DMux4Way steers the load signal, and a Mux4Way16 routes the selected memory component's output to out.
  • Computer.hdl: Instantiates ROM32K, CPU, and Memory. The PC feeds the ROM address; ROM instruction feeds the CPU; CPU memory signals (outM, writeM, addressM) connect directly to Memory.

1. Assembler Architecture (Two-Pass Design)

The assembler (assembler.py) was developed independently in Python without relying on external libraries or the official Java assembler tool:

  • Pass 1 (Label & Symbol Processing): Iterates through the assembly source, strips comments (//...) and whitespace, and identifies label declarations (LABEL). Labels are bound to the current ROM instruction address in the symbol table without advancing the ROM program counter. Predefined symbols (SP, LCL, ARG, THIS, THAT, R0..R15, SCREEN=16384, KBD=24576) are pre-populated.
  • Pass 2 (Binary Code Generation): Translates remaining instructions into 16-bit binary words:
    • A-instructions (@val): If numeric constant ($0 \le v \le 32767$), converted to binary 0vvvvvvvvvvvvvvv. If symbolic, resolved via the symbol table. Unseen variables are dynamically allocated in RAM sequentially starting from address 16.
    • C-instructions (dest=comp;jump): Encoded into 111 a c1..c6 d1..d3 j1..j3 using comprehensive lookup dictionaries covering all 28 Hack ALU operations.

2. Additional Feature: Line-Number Invalid Instruction Error Handling

For $K \bmod 3 = 46 \bmod 3 = 1$, the assembler strictly validates every instruction, destination field, ALU computation mnemonic, jump mnemonic, and symbol name. When an invalid instruction is encountered, it outputs Line <N>: invalid instruction and halts with exit code 1 without writing a misleading partial .hack file.

1. Box Program Logic & Screen Memory Addressing

The program Box.asm continuously polls the memory-mapped keyboard address KBD (24576). If a key is detected (KBD != 0), color is set to $-1$ (0xFFFF, black pixels). If no key is pressed (KBD == 0), color is set to $0$ (0x0000, white pixels).

The drawing routine initializes a pointer row_ptr to 17856 ($16384 + 32 \times 46$) and sets a loop counter row_count = 20. For each of the 20 rows, it writes color into three consecutive words (row_ptr, row_ptr + 1, row_ptr + 2), advances the row pointer by 30 words ($2 + 30 = 32$ words per screen line), and decrements the counter. The last modified address is exactly 18466 ($16384 + 32 \times 65 + 2$).

2. Programming Mistake Encountered and Corrected

Actual Encountered Issue: When implementing the three-word horizontal write per row, an initial attempt was made to address consecutive words using A=M+1 and A=M+2 directly after writing Word 0. In Hack assembly, M always refers to RAM[A]. Because register A had already been changed to point to the screen memory address rather than the pointer variable row_ptr, referencing M read the contents of the screen memory rather than the pointer value. This corrupted the drawing address. The bug was corrected by explicitly loading row_ptr, incrementing it with M=M+1, and setting A=M for each word, followed by advancing row_ptr by 30 words at the end of each row.

CPU.hdl (Hack CPU Implementation)
CHIP CPU {
    IN  inM[16], instruction[16], reset;
    OUT outM[16], writeM, addressM[15], pc[15];

    PARTS:
    // Type of instruction: 0 = A, 1 = C
    Not(in=instruction[15], out=isA);
    Not(in=isA, out=isC);

    // A Register input selection and load
    Mux16(a=instruction, b=aluOut,
          sel=instruction[15], out=inA);
    And(a=isC, b=instruction[5], out=isCDestA);
    Or(a=isA, b=isCDestA, out=loadA);
    ARegister(in=inA, load=loadA, out=outA,
              out[0..14]=addressM);

    // D Register load control
    And(a=isC, b=instruction[4], out=loadD);
    DRegister(in=aluOut, load=loadD, out=outD);

    // ALU input operand selection (A vs M)
    Mux16(a=outA, b=inM, sel=instruction[12],
          out=aluY);

    // ALU Execution
    ALU(x=outD, y=aluY,
        zx=instruction[11], nx=instruction[10],
        zy=instruction[9],  ny=instruction[8],
        f=instruction[7],   no=instruction[6],
        out=aluOut, out=outM, zr=zr, ng=ng);

    // Write to memory flag (d3 in C-instruction)
    And(a=isC, b=instruction[3], out=writeM);

    // Jump condition evaluation
    Or(a=zr, b=ng, out=zrOrNg);
    Not(in=zrOrNg, out=pos);
    And(a=instruction[2], b=ng, out=jlt);
    And(a=instruction[1], b=zr, out=jeq);
    And(a=instruction[0], b=pos, out=jgt);
    Or(a=jlt, b=jeq, out=jle);
    Or(a=jle, b=jgt, out=jumpCond);
    And(a=isC, b=jumpCond, out=doJump);

    // Program Counter update
    PC(in=outA, load=doJump, inc=true,
       reset=reset, out[0..14]=pc);
}

class AssemblyError(Exception):
    def __init__(self, line_num, message="invalid instruction"):
        super().__init__(f"Line {line_num}: {message}")
class HackAssembler:
    def assemble(self, asm_source_lines):
        self.symbol_table = dict(PREDEFINED_SYMBOLS)
        self.next_var_address, self.num_labels, self.num_variables = 16, 0, 0
        rom_address, cleaned_instructions = 0, []

        # PASS 1: Labels & Symbol Resolution
        for line_idx, raw_line in enumerate(asm_source_lines):

            cleaned = raw_line.split("//")[0].strip()
            if not cleaned: continue
            if cleaned.startswith("(") and cleaned.endswith(")"):
                label = cleaned[1:-1].strip()
                if not label or not SYMBOL_REGEX.match(label) or label in self.symbol_table:
                    raise AssemblyError(line_num, "invalid instruction")
                self.symbol_table[label] = rom_address
                self.num_labels += 1
            else:
                cleaned_instructions.append((line_num, cleaned))
                rom_address += 1
        # PASS 2: Binary Code Translation
        binary_code = []
        for line_num, inst in cleaned_instructions:
            if inst.startswith("@"):
                val_str = inst[1:].strip()
                if val_str.isdigit():
                    val = int(val_str)
                    if val < 0 or val > 32767:
                        raise AssemblyError(line_num, "invalid instruction")
                elif SYMBOL_REGEX.match(val_str):
                    if val_str not in self.symbol_table:
                        self.symbol_table[val_str] = self.next_var_address
                        self.next_var_address += 1
                        self.num_variables += 1
                    val = self.symbol_table[val_str]
                else: raise AssemblyError(line_num, "invalid instruction")
                binary_code.append(f"0{val:015b}")
            else:
                s = "".join(inst.split())
                dest_p, jump_p, comp_p = "", "", ""
                if "=" in s: dest_p, s = s.split("=", 1)
                if ";" in s: comp_p, jump_p = s.split(";", 1)
                else: comp_p = s
                if dest_p not in DEST_TABLE or comp_p not in COMP_TABLE or jump_p not in JUMP_TABLE:
                    raise AssemblyError(line_num, "invalid instruction")
                binary_code.append(f"111{COMP_TABLE[comp_p]}{DEST_TABLE[dest_p]}{JUMP_TABLE[jump_p]}")
        return binary_code
